# Sticker Showcase — SEO & GEO Strategy

Living strategy for <https://sutekka-generator.vercel.app/>.
Owner: webmaster (Muse). Goal: every sticker set is friendly to search
crawlers **and** to agent bots (AI search, assistants, answer engines),
so the sets are indexed, cited and surfaced — not just ranked.

SEO = being found by search engines. GEO = being understood and cited by
generative engines (ChatGPT, Claude, Perplexity, Google AI Overviews).
The two share most mechanics; GEO adds machine-readable structure,
full-text sources, and explicit bot access.

## Principles

1. **Static and complete.** Every crawlable page is a static file with
   its full content in the HTML — no client-side fetching. If a crawler
   or agent cannot see it in the first response, it does not exist.
2. **One canonical URL per set.** The reader is hash-routed
   (`/#/set/<slug>`); fragments are never sent to a server and never
   indexed. So each set's crawlable URL is its share page,
   `/share/<slug>/`, and that page carries the canonical. No duplicate
   paths, no query-string variants.
3. **Structured before styled.** JSON-LD describes every crawlable
   page's type before any visual work. A page without its schema is
   unfinished.
4. **Bots are guests, not intruders.** Named agent bots are explicitly
   allowed in robots.txt. Nothing that powers search or answers is
   blocked. Only one pure bulk-training scraper with a poor reputation
   is excluded, and the exclusion is listed here, not hidden.
5. **No invented facts.** Dates, figures and claims in structured data
   come from the same verified records as `index.json` (brief, QA,
   script). A wrong figure in structured data is worse than none.
6. **Regenerated, not hand-edited.** Every SEO/GEO file is produced by
   `scripts/build_sticker_index.py` from the set records, so publishing
   a new set updates search visibility with no extra step. Hand-editing
   a generated file is a bug; the next build overwrites it.

## The hash-routing constraint

The site is a single-page app: the homepage grid and the reader are
JavaScript views behind `#/` fragments. Search engines and link-preview
crawlers do not run the app, so they can never see a set through the
reader URL. The crawlable surface is deliberately small:

| URL | What it is | Crawlable? |
| --- | --- | --- |
| `/` | Homepage (static HTML + JS grid) | Yes — meta, OG, WebSite JSON-LD |
| `/share/<slug>/` | One static page per set | Yes — the set's canonical URL |
| `/#/set/<slug>` | Reader view (JS only) | No — fragments are never indexed |
| `/#/about` | About view (JS only) | No — same reason |
| `/data/index.json`, `/data/inventory.json` | Machine-readable data | Yes — linked from llms.txt |
| `/stickers/<slug>/…`, `/og/…`, `/thumbs/…` | Images | Yes — referenced by share pages |

The About text lives in the JS view, so it is not indexed; its
substance is repeated in `llms.txt` instead.

## Crawler & agent-bot policy

`web_app/robots.txt` is generated by the build script (single source of
truth: `AGENT_BOTS` / `BLOCKED_BOTS` in
`scripts/build_sticker_index.py`). Current rules:

- `*`: `Allow: /` — the whole site is public content; nothing is
  disallowed except the one bot below.
- Explicit `Allow: /` rules for every named bot below, so an agent
  never has to guess whether it is welcome:
  - OpenAI: `GPTBot`, `ChatGPT-User`, `OAI-SearchBot`
  - Anthropic: `ClaudeBot`, `anthropic-ai`, `Claude-Web`
  - Google: `Google-Extended` (AI training/search features)
  - Perplexity: `PerplexityBot`, `Perplexity-User`
  - Apple: `Applebot-Extended`
  - Meta: `Meta-ExternalAgent`, `Meta-ExternalFetcher`
  - Common Crawl: `CCBot` (feeds many search indexes)
  - Cohere: `cohere-ai`
  - You.com: `YouBot`
  - DuckDuckGo: `DuckAssistBot`
- Excluded (deliberate, review yearly): `Bytespider` — bulk-training
  crawler with a record of ignoring crawl limits. If ByteDance
  publishes a search/answer product that needs it, re-evaluate.
- Sitemap is declared in robots.txt:
  `https://sutekka-generator.vercel.app/sitemap.xml`.

## Per-page checklist

### Homepage `/` (`web_app/index.html`, hand-written)

| Check | Rule |
| --- | --- |
| Title | `Sticker Showcase — 贴纸展 · 时事专栏变成的贴纸` |
| Description | One sentence, what the site is, for a human scanning results |
| Canonical | `https://sutekka-generator.vercel.app/` |
| Open Graph | `og:type` website, `og:title`, `og:description`, `og:image` → `/og/site.jpg` (1200×604, regenerated from the newest set's sheet on every build), `og:url` |
| Twitter | `summary_large_image` + title/description/image |
| JSON-LD | `WebSite` (name, description, url, `inLanguage` zh-CN) |
| H1 | Exactly one (`时事专栏，变成贴纸。`) |
| Language | `lang="zh-CN"` on `<html>`; content is zh-first with EN toggles |

### Share page `/share/<slug>/` (generated per set)

| Check | Rule |
| --- | --- |
| Title | Share hook title when present, else set title, + `— Sticker Showcase` |
| Description | Share hook teaser when present, else the set angle (≤200 chars) |
| Canonical | `https://sutekka-generator.vercel.app/share/<slug>/` |
| Open Graph | `og:type` article, hook title/teaser, `og:image` → `/og/<slug>.jpg` (1200×604), `og:image:width/height`, `og:url`, `og:locale` (zh-CN / en), `article:published_time` (batch date, +08:00) |
| Twitter | `summary_large_image` + title/description/image |
| JSON-LD | `CreativeWork` + `BreadcrumbList` (see schema map) |
| H1 | Exactly one (the hook title) |
| Body content | Angle paragraph + the full 8-sticker list (title — Japanese / Chinese) + cast line, so the page is a real document for a no-JS crawler, not just a tag carrier. Humans are redirected to the reader by JS before reading it. |
| Redirect | JS-only `location.replace`; no `<meta refresh>`, so crawlers stay on the page and read it |

### No index blocks

No `noindex` / `nofollow` anywhere — grep before every deploy.

## Schema map (JSON-LD)

| Page | Schema | Where |
| --- | --- | --- |
| Homepage `/` | `WebSite` | `web_app/index.html` (static) |
| Share page `/share/<slug>/` | `CreativeWork` + `BreadcrumbList` | `share_page_json_ld()` in the build script |

The share page's `CreativeWork` carries: `name` (set title),
`description` (teaser/angle), `url` (share URL), `image` (OG card),
`inLanguage`, `datePublished` (batch date), `author` (Organization
"Sticker Showcase"), and `hasPart` — one `ImageObject` per sticker
with `contentUrl` (the staged sticker PNG) and `caption` (Japanese
line / Chinese line). The `BreadcrumbList` is Home › set.

## Machine-readable content (GEO)

- **`web_app/llms.txt`** — the index for LLMs: site summary (how a
  set is made, QA bar, honesty rule), every set with its share-page
  URL and one-line angle, plus links to `llms-full.txt` and the
  sitemap. Regenerated on every build.
- **`web_app/llms-full.txt`** — the full content: site summary + for
  every set its title, set/reader URLs, QA score, tags, cast, angle,
  the **column verbatim**, the **research brief**, and the full
  sticker list (title, Japanese, Chinese, point, image URL). This is
  the GEO payload: an agent can answer from the site's own checked
  facts instead of guessing. Regenerated on every build.
- **`web_app/sitemap.xml`** — homepage (`priority` 1.0, daily) + one
  `/share/<slug>/` per set (`priority` 0.8, monthly, `lastmod` = the
  batch date). No hash routes, no `.txt` files — it is for HTML pages.
- **`web_app/data/index.json` / `inventory.json`** — the structured
  data behind the site; linked from llms.txt for agents that want the
  raw records.

## How it regenerates

`scripts/build_sticker_index.py` is the only writer. On every run
(and on every Vercel build, via `buildCommand`) it regenerates:

- `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`
  (via `write_if_changed` — untouched when the content is identical)
- every set's share page (JSON-LD + body content included)
- `og/site.jpg` (homepage OG card, from the newest set's sheet;
  1200×604 because every sheet is 3320×1672)

`--check` mode verifies all four text files are fresh, like it does
for `index.json` / `inventory.json`. The deploy helper
(`deploy_sutekka.py`) excludes the regenerated paths from the upload
tarball — Vercel's build recreates them — so the 100 MB single-file
upload limit stays out of reach as sets accumulate.

Cache headers (`vercel.json`): `/robots.txt`, `/sitemap.xml`,
`/llms.txt`, `/llms-full.txt` are `public, max-age=3600,
stale-while-revalidate=86400` — fresh within an hour of a publish.
Share pages are `max-age=0, must-revalidate` (already the case).

## Verification (after every publish)

```sh
# Crawler policy + sitemap resolve and list every set
curl -s https://sutekka-generator.vercel.app/robots.txt
curl -s https://sutekka-generator.vercel.app/sitemap.xml
# LLM index files
curl -s https://sutekka-generator.vercel.app/llms.txt
curl -s https://sutekka-generator.vercel.app/llms-full.txt | head -40
# Share page carries JSON-LD + canonical + published time
curl -s https://sutekka-generator.vercel.app/share/ai-agent-four-faces/ \
  | grep -o "application/ld+json\|rel=\"canonical\"\|article:published_time" | sort -u
# Homepage OG card resolves
curl -s -o /dev/null -w "%{http_code}\n" \
  https://sutekka-generator.vercel.app/og/site.jpg
```

Also: fetch a share URL with a link-preview debugger (X / Facebook /
LinkedIn) after a publish — the card image is the first thing a
human sees, and a stale card is a silent failure.

## Open items & limits

- **Custom domain.** Everything uses `SITE_URL` in the build script
  (`https://sutekka-generator.vercel.app`). If a custom domain lands
  (e.g. `stickers.gobblemon.com`), change that one constant, rebuild,
  and every canonical, OG URL, sitemap entry and llms link follows.
  Do not hand-edit a generated URL anywhere else.
- **Homepage OG image is the newest set.** `/og/site.jpg` tracks the
  newest set by design — the homepage card always shows the latest
  work. If the homepage ever needs a fixed brand card, generate a
  separate `og/home.jpg` and point `index.html` at it instead.
- **The reader is not indexed, by design.** A set's search presence
  is its share page. Do not add hash routes to the sitemap, and do
  not expect `/#/set/<slug>` to rank.
- **About is not indexed.** The About view is JS-only; its substance
  (three-agent pipeline, QA bar, honesty rule) is in `llms.txt`.
- **GA id is shared with the comic site** (`G-L4BV4T8QQ5`) — split it
  before any ad spend; unrelated to crawling, noted here so it is not
  forgotten.
